Update Set Operations

Managing Update Sets in ServiceNow often involves moving records that aren't natively captured or deploying update sets across environments automatically. This guide details how to perform these operations using both Background Scripts and NodeJS integrations via the CI/CD Spoke APIs.

1. Adding Multiple Existing Records to an Update Set (Background Script)​

Sometimes you need to retroactively add several records to a specific update set. The GlideUpdateManager2 API allows you to force a record into the current active update set.

APIs Used:

  • GlideUpdateManager2().saveRecord() - Adds a given GlideRecord to the current update set.

[!WARNING] Before running this script, ensure you have selected the correct Update Set as your "Current" active update set in the ServiceNow UI.

javascript
// Example: Adding specific records (e.g., from an item_option_new table) to the update set
var gr = new GlideRecord('sys_update_set');
// Modify the query below to target the records you wish to force into the update set
gr.addEncodedQuery("nameSTARTSWITH<update_set_name>");
gr.query();

var um = new GlideUpdateManager2();

// Loop through the query results and add each record to the current update set
while (gr.next()) {
    var recSysID = gr.getUniqueValue();
    gs.info("Adding record to update set: " + recSysID); 
    
    // Save to current update set
    um.saveRecord(gr);
}
gs.info("Added all records from table to the current update set");

2. Resolving Update Set Retrieval Mutex Errors​

Occasionally, when retrieving update sets from another instance, the process hangs or fails with the error: Update set retrieve is unavailable because another operation 'Committing update set: <Update_Set_name>' is running

This happens when a mutex lock is not properly released.

Fix:

  1. Navigate to sys_mutex.LIST in the filter navigator.
  2. Search for the record with the name update-mutex.
  3. Delete that record from the sys_mutex table to release the lock.

3. CI/CD: Automated Update Set Deployment (NodeJS)​

Instead of manually retrieving, previewing, and committing Update Sets via the UI, you can fully automate the process using the sn_cicd REST APIs.

The following NodeJS script takes an Update Set sys_id and orchestrates the deployment from an origin instance to a target instance.

APIs Used:

  • GET /api/now/table/sys_update_set - Validates the update set is marked "Complete" on the origin.
  • GET /api/now/table/sys_update_set_source - Finds the update source record on the target instance.
  • POST /api/sn_cicd/update_set/retrieve - Triggers retrieval and auto-preview.
  • POST /api/sn_cicd/update_set/commit/{remote_update_set_id} - Commits the retrieved update set.

[!NOTE] This requires the ServiceNow CI/CD Spoke plugin to be active on the target instance.

javascript
import { request as _request } from "https";

// ... (readline setup omitted for brevity - see full repository for interactive prompts) ...

async function deployUpdateSet(updateSetId, originInstance, targetInstance, user, pass) {
  // Step 1: Validate update set is marked complete on origin
  console.log(`\n[Step 1] Validating update set is complete on ${originInstance}...`);
  const valRes = await request(originInstance, "GET",
    `/api/now/table/sys_update_set?sysparm_query=sys_id=${updateSetId}&sysparm_fields=name,state&sysparm_limit=1`
  );
  const usRecord = valRes.body?.result?.[0];
  if (usRecord.state !== "complete") throw new Error(`Update set is not complete.`);

  // Step 2: Get update set source for origin on target
  console.log(`\n[Step 2] Fetching update source for ${originInstance} from ${targetInstance}...`);
  const srcRes = await request(targetInstance, "GET",
    `/api/now/table/sys_update_set_source?sysparm_fields=sys_id,name,instance_id&sysparm_query=active=true^urlLIKE${originInstance}.service-now.com`
  );
  const updateSourceId = srcRes.body?.result[0].sys_id;
  const updateSourceInstanceId = srcRes.body?.result[0].instance_id;

  // Step 3: Retrieve update set on target with auto_preview + cleanup
  console.log(`\n[Step 3] Retrieving update set on ${targetInstance}...`);
  const retrieveRes = await request(targetInstance, "POST",
    `/api/sn_cicd/update_set/retrieve?update_set_id=${updateSetId}&update_source_id=${updateSourceId}&update_source_instance_id=${updateSourceInstanceId}&auto_preview=true&cleanup_retrieved=true`
  );
  
  // The API is asynchronous; it returns a progress URL.
  const progressUrl = retrieveRes.body?.result?.links?.progress?.url;

  // Step 4: Poll retrieve/preview progress (Helper function repeatedly calls GET on progressUrl)
  console.log(`\n[Step 4] Polling retrieve + preview progress...`);
  const progressResult = await pollProgress(targetInstance, progressUrl);
  
  // Extract the remote update set ID once preview completes
  const remoteUpdateSetId = progressResult.remote_update_set_id || progressResult.links?.result?.id;

  // Step 5: Commit remote update set
  console.log(`\n[Step 5] Committing remote update set ${remoteUpdateSetId}...`);
  const commitRes = await requestWithBody(targetInstance, "POST",
    `/api/sn_cicd/update_set/commit/${remoteUpdateSetId}`,
    { force_commit: "true" }
  );
  const commitProgressUrl = commitRes.body?.result?.links?.progress?.url;
  
  // Poll commit progress
  await pollProgress(targetInstance, commitProgressUrl);

  console.log("\n✓ Update set deployed successfully.");
}
